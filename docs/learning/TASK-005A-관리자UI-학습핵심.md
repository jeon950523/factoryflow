# TASK-005A 학습 핵심 — 구현 후 읽기

1. **프론트 담당 범위:** Vue Controller 역할은 사용자 입력·상태 표시·API 호출. 재고 계산, 멱등성, 잠금·트랜잭션은 Spring/MySQL에서 처리.
2. **왜 목록 API가 필요한가:** `GET /work-orders/{id}`를 수십 번 호출하면 네트워크 왕복 및 BOM 조회가 중복된다. 목록 전용 응답 DTO + 페이지 조회로 필요한 열만 전달.
3. **상태별 액션 버튼:** DRAFT에서는 예약·취소, RESERVED에서는 생산 시작·취소, IN_PROGRESS에서는 생산 완료, AWAITING_QC에서는 품질검사. 프론트 UI는 편의 장치이며 서버 상태 검증이 최종 방어.
4. **요청 키 재사용:** 입고·출고 저장 버튼을 반복 누르거나 네트워크 장애로 응답이 사라져도 같은 요청 키는 동일 작업으로 판단. 실패 직후 임의로 키를 새로 생성하지 않음.
5. **목록→상세 화면:** 실제 ERP들이 쓰는 패턴을 참고해 화면 위치·상태·다음 행동을 명확하게 표시. 대시보드 숫자는 API 결과만 사용.
6. **API 프록시와 Vercel:** 로컬 Vite에서 `/api` 프록시를 제공하므로 개발 CORS 우회 설정이 필요 없음. 배포 브라우저의 API 엔드포인트와 인증/CORS는 별도 설계 필수.
7. **장점:** 구현 구조가 단순하고 책임이 명확. **단점:** 첫 100개 품목만 셀렉트 옵션에 보임, 초기 대시보드가 복수 API 요청, 실제 브라우저 QA 필요.
8. **리팩터링:** 검색형 서버 옵션, 요청 캐싱/취소, 폼 검증 공통화, 접근성 테스트는 2차 작업.

면접 설명 요약: 'ERP/Odoo 같은 제조 관리 UI를 참고해 업무별로 탐색을 나누고 목록과 상세 및 상태별 작업을 연결했습니다. 모든 수량 정합성 검증은 기존 Spring Boot API에서 수행하고, 화면은 실제 DB 응답만 표시하도록 설계했습니다.'
