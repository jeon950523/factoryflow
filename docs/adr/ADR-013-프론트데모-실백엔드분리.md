# ADR-013 — Vercel 체험 데모와 실제 Java 백엔드 검증 분리

상태: **선택 (2026-11-12)**

## 배경
공개 포트폴리오 도메인 `factoryflow.kro.kr`의 Vercel 프론트는 연결되었지만, Oracle Cloud 가입 과정이 계속 막혀 Spring Boot/MySQL VM을 생성하지 못했다.

## 선택
1. 기존 Java21/Spring Boot/MySQL 코드, 인증/인가와 Testcontainers CI를 유지한다.
2. Vercel 운영 프론트에서는 방문자별 IndexedDB 샘플로 공장 업무 흐름을 시뮬레이션한다.
3. 프론트 API 게이트웨이(`src/lib/api.js`)에서 Vite 모드에 따라 분기한다. 로컬 dev는 기존 서버 API, 프로덕션 기본은 데모.
4. 브라우저 데모에서는 서버 계정·JWT·비밀번호를 저장하지 않고 자동 샘플 체험을 사용한다. 서버 인증과 혼동하지 않도록 안내한다.
5. 브라우저 데이터는 IndexedDB 1개 상태 스냅샷을 단일 readwrite 트랜잭션으로 갱신한다. 실패 시 PUT하지 않는 순수 엔진으로 구성한다.
6. 임시 데모를 실제 서버 구현의 대체 성과로 포장하지 않는다. 별도 CI 증거로 구분한다.

## 대안 검토
- GitHub Actions를 웹서버로 활용: 러너는 임시 실행환경이므로 상시 웹 서비스가 되지 않는다.
- Vercel+localStorage만: 구조화된 업무 상태와 원자적 저장/다중 탭 쓰기 제어에 불리.
- Vercel+IndexedDB로 실제 Spring 서비스 대체: 백엔드 동시성/인증 포트폴리오 가치가 사라지므로 부적절.
- **결정: 실백엔드는 유지하고, 방문자 UX를 위한 별도 IndexedDB 데모를 제공**.

## 제약
사용자 브라우저의 저장량·삭제·시크릿 모드 정책에 영향을 받으며 여러 방문자의 데이터는 공유할 수 없다. JS 데모 엔진이 실제 Spring 트랜잭션/잠금과 일치한다고 주장하지 않는다.

## 후속 작업
운영 호스트를 확보하면 `VITE_DEMO_MODE=false`로 프론트를 빌드하고 동일 출처 API 프록시, TLS, Secure Cookie, 관리자 복구, 백업·복원 실환경 테스트를 통과시킨다.
