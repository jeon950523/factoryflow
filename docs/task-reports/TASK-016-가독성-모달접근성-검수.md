# TASK-016 — 공통 UI 가독성·모달 키보드 접근성 검수

- 대상: FactoryFlow `main` / TASK-015 병합 커밋 `2899b020`
- PR: https://github.com/jeon950523/factoryflow/pull/23
- 변경 범위: Vue UI, 공통 포커스 지시어, 가독성 CSS, 브라우저 회귀 테스트
- 제외 범위: Spring Boot, MySQL, 인증·제조·LOT·FIFO·출고 처리, IndexedDB 엔진 및 API 계약
- 공개 사이트: https://factoryflow.kro.kr (PR 코드 반영 여부와 화면 스모크는 배포 후 따로 검증)

## 1. 발견한 문제 및 원인

- 품목/BOM, 입고, 생산지시, 출고, 계정 발급 모달이 각 페이지에서 열고 닫히지만 첫 입력 초점, Tab 순환, Escape 동작, 닫힘 후 트리거로 초점 복귀가 통일돼 있지 않았다.
- 생산지시와 계정 발급은 저장 중 백드롭/닫기 클릭 시 모달을 숨길 수 있어, 쓰기 요청과 사용자 인터페이스 상태가 분리되는 위험이 있었다.
- 품목 검색 선택자는 `@keydown.esc.stop.prevent`로 열림 여부와 무관하게 Escape를 소비하여, 닫힌 검색 선택자에 초점이 있을 때 상위 모달 Escape 닫기가 차단됐다.
- 공통/업무별 CSS의 보조 안내 글씨가 10~11px이고 대비가 낮은 곳이 있어, 목록과 상세의 의미를 빠르게 읽기 어려웠다.

## 2. 수정 구현

1. `frontend/src/directives/dialogFocus.js` 공통 지시어를 생성해 다섯 화면의 모달에 연결한다. 첫 필드에 초점을 두고, Tab/Shift+Tab을 모달 안에서 순환시키며, Escape 닫기와 닫힘 후 원래 클릭 버튼으로 복귀를 지원한다. 별도 이벤트 등록은 언마운트 시 반드시 해제한다.
2. 저장 중에는 Escape/백드롭/닫기 버튼으로 등록 UI가 사라지지 않도록 페이지의 기존 `saving` 상태를 단일 진실원으로 사용한다. API 전송·검증·응답 변경은 없다.
3. `ItemSearchSelect`에서 열린 검색 팝업은 Escape 한 번으로 닫고, 닫혀 있으면 이벤트를 상위 모달까지 전달한다.
4. `frontend/src/assets/accessibility.css`에 화면 전체 재설계 대신 보조 문구와 이력 메타데이터의 최소 글씨 크기 및 색상 대비를 보완한다. 보조기기 사용자의 `prefers-reduced-motion` 설정을 고려한다.
5. `frontend/src/main.js`에서 전역 Vue 지시어와 추가 CSS를 등록한다. 각 페이지 템플릿은 최소한으로 변경한다.

## 3. 안정성과 접근성 검수

| 검수 지점 | 의도한 결과 |
|---|---|
| 모달 오픈 | 기존 트리거 기억 후 모달 첫 입력에 초점 |
| Tab / Shift+Tab | 첫 요소와 마지막 요소 사이 순환, 배경으로 이탈하지 않음 |
| Escape | 열린 품목 검색은 우선 닫고, 다음 Escape는 모달 닫음 |
| 저장 중 | Escape·백드롭·취소/닫기 버튼으로 처리 중 UI 숨김 불가 |
| 모달 종료 | 트리거가 현재 DOM에 남아 있으면 초점 복귀 |
| 언마운트 | 문서 이벤트 리스너를 해제해 중복/누수 방지 |
| 가독성 | BOM·출고·이력 설명과 셀 보조 정보 12px 이상 및 더 짙은 색 |
| 회귀 | 기존 품목/BOM·제조·출고·이동 이력 흐름 변경 없음 |

## 5. 시니어 코드 검수 및 리팩터링 판단

**안전성:** 백엔드나 데이터 처리 엔진이 아닌 Vue UI 포커스 수명주기만 분리했다. 저장이 끝나지 않았는데 닫힌 UI로 오인하게 하는 위험을 줄였다. `document` 리스너는 모달이 마운트된 동안에만 동작한다.

**기능 리팩터링:** 여전히 모달 형태와 저장 요청은 각 페이지가 책임진다. 상태를 강제로 통합하거나 서버 재시도를 덮어쓰지 않았다. 추후 모달이 여러 단계로 복잡해진다면 별도 `Dialog` 컴포넌트로 UI 구조를 통합할 수 있다.

**효율 리팩터링:** 접근성 CSS는 장기적으로 보조 색상·타이포그래피 디자인 토큰에 합치는 것이 좋다. 이번에는 기존 업무별 CSS를 광범위하게 수정하지 않도록 별도 덮어쓰기로 제한했다. 모달 키보드 리스너는 활성 모달당 하나만 등록되므로 평상시 부하는 없다.

**잔여 검증 범위:** 공개 Vercel 배포, Windows Chrome 실제 폰트와 화면 배율 125%/150%, 모든 보조기기 읽기 순서는 별도 사용자 환경 검증이 필요하다. 공식 WCAG 적합성 전체 인증을 의미하지 않는다.

## 6. 30초 설명

“기존 화면의 다섯 등록·발급 모달은 사용자가 키보드만으로 조작할 때 초점이 빠져나가거나 닫힌 검색 선택자에서 Escape가 막혔습니다. 공통 포커스 지시어로 초점 이동·복귀·Escape 처리와 저장 중 닫힘 방어를 통일했고, ERP 업무표의 보조 정보 가독성도 개선했습니다. 제조 로직은 유지한 채 Chrome 데모와 실제 MySQL E2E로 회귀 검증합니다.”
